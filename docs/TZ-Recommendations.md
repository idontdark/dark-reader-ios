# Дополнение к ТЗ: рекомендации, жанры и персонализация

## 17. Полностью переработать систему рекомендаций книг

В приложении имеются разделы:

- Для вас
- Популярное
- Новинки
- Жанры

**Сейчас книги могут отображаться случайным образом, без соответствия выбранным интересам пользователя. Это необходимо полностью исправить.**

### 17.1. Раздел «Для вас»

Реализовать настоящую персональную рекомендательную систему.

Учитывать:

- Жанры, выбранные на экране приветствия.
- Прочитанные и прослушанные книги.
- Книги, добавленные в библиотеку.
- Любимых авторов и серии.
- Историю поиска.
- Оценки пользователя, если они предусмотрены.
- Язык книг.
- Предпочтения отдельно для электронных книг и аудиокниг.

**Не показывать случайные книги только ради заполнения раздела.**

Для нового пользователя рекомендации первоначально формируются по жанрам, выбранным при регистрации.

По мере использования приложения рекомендации должны становиться точнее.

Не рекомендовать уже прочитанное без необходимости. Не допускать постоянного повторения одних и тех же произведений.

### 17.2. Раздел «Популярное»

Отображать действительно популярные книги.

Использовать достоверные показатели:

- Рейтинги и число оценок.
- Популярность в доступных каталогах.
- Статистику добавлений в библиотеку.
- Количество прочтений и прослушиваний, если такие данные действительно собираются.

Не генерировать случайные значения рейтингов и популярности.

Если достоверных данных недостаточно, не выдавать случайную подборку за рейтинг популярных книг.

Желательно учитывать популярность отдельно для русского и других языков.

### 17.3. Раздел «Новинки»

Показывать действительно новые произведения или издания.

Основной критерий — дата публикации произведения либо конкретного издания.

Не путать:

- Дату публикации книги.
- Дату появления книги на сайте.
- Дату её добавления в приложение.

Старую книгу, недавно появившуюся в каталоге, не считать литературной новинкой.

Для аудиокниг дополнительно учитывать дату выпуска аудиоверсии.

Если год или дата неизвестны, не включать книгу в подборку новинок без обоснования.

### 17.4. Раздел «Жанры»

Реализовать корректную классификацию произведений.

Книги должны соответствовать выбранному жанру по реальным метаданным.

Примеры:

| Жанр | Что должно отображаться |
|---|---|
| История | Историческая литература, исследования, документальные книги |
| Детективы | Расследования, криминальные романы |
| Фантастика | Научная фантастика, космическая фантастика |
| Фэнтези | Магия, вымышленные миры, фэнтезийные произведения |
| Биографии | Биографии, мемуары |
| Психология | Книги по психологии |
| Бизнес | Предпринимательство, управление, экономика |

**Пример существующей ошибки:** при выборе жанра «История» приложение предлагает «Гарри Поттера».

Это недопустимо. «Гарри Поттер» относится к фэнтези, а не к исторической литературе.

Использовать жанровые метаданные источников, нормализацию категорий и проверенную классификацию. Не определять жанр только по названию произведения.

Различать историческую литературу и исторические романы, если в каталоге предусмотрены отдельные категории.

## 18. Исправить рекомендации на экране приветствия

После выбора любимых жанров пользователь должен получать **реальные рекомендации, соответствующие выбранным интересам**.

Например, если выбран жанр «История», предлагать:

- «История государства Российского» — Николай Карамзин.
- «SPQR. История Древнего Рима» — Мэри Бирд.
- «Sapiens. Краткая история человечества» — Юваль Ной Харари.
- «Вторая мировая война» — Энтони Бивор.

Эти названия приведены как примеры тематически подходящих произведений, а не как обязательный список. Перед показом проверять наличие книги и соответствие языка.

Если пользователь выбрал несколько жанров, рекомендации должны включать произведения из каждого выбранного жанра, а не только одного.

Требования:

1. Загружать реальные книги из подключённых источников.
2. Использовать настоящие обложки и метаданные.
3. Проверять соответствие выбранным жанрам.
4. Учитывать язык пользователя.
5. Исключать дубликаты.
6. Не показывать недоступные книги как доступные.
7. Не подменять отсутствующие результаты случайными произведениями.

Если подходящих книг недостаточно, показывать меньше рекомендаций, но качественных.

## 19. Механизм рекомендаций

Создать отдельный сервис `RecommendationEngine` на Swift.

Он должен:

- Получать сведения о книгах из доступных источников.
- Нормализовать жанры разных каталогов.
- Сопоставлять книги с интересами пользователя.
- Вычислять релевантность результатов.
- Учитывать популярность и качество метаданных.
- Исключать неподходящие жанры.
- Обеспечивать разнообразие авторов и произведений.
- Обновлять подборки при изменении пользовательских предпочтений.

Не требуется сразу подключать внешнюю платную нейросеть. Сначала реализовать качественный алгоритм на основе реальных данных, жанров и истории взаимодействий.

**Все рекомендации должны иметь объяснимую причину появления в подборке.**

## 20. Обязательная проверка качества

Протестировать рекомендации минимум для десяти разных жанров.

Для каждого жанра проверить не менее двадцати предложенных произведений.

Проверить следующие сценарии:

- Пользователь выбирает только «История».
- Пользователь выбирает только «Фэнтези».
- Пользователь выбирает несколько жанров.
- Новый пользователь ещё ничего не читал.
- Пользователь уже прочитал несколько книг.
- Пользователь меняет любимые жанры.
- Пользователь переключает язык.
- В одном из источников отсутствуют подходящие книги.
- Включено несколько источников с одинаковыми произведениями.

**Критерий готовности:** после выбора «История» приложение предлагает историческую литературу, после выбора «Фэнтези» — фэнтези. Разделы «Популярное» и «Новинки» используют реальные основания для сортировки, а «Для вас» учитывает предпочтения и историю пользователя.

Не использовать случайные книги для искусственного заполнения разделов.
